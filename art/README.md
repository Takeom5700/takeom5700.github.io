# 無銘（`/art/`）

一つの式から生まれ続ける映像作品。物語も説明も筋もない。
画面には題名も操作も出さない。触れると始まり、8分半で一つが終わり、
次の種の作品が始まる。**同じものは二度出ない。**

公開URL: `https://takeom5700.github.io/art/`

映像ファイルではない。**その場で計算している。**
1280×720 の動画を再生しているのではなく、画素ごとに光の通り道をたどって
毎フレーム焼いている。だから 8分半の作品を何千本でも置けるし、
どれも誰も見たことがない。

外部ライブラリなし。画像・動画・音声ファイルなし。音も全部その場で合成している。
`art/` の中だけで完結していて、他のどこにも依存していない。

---

## アートの本質 —— この作品が何に賭けているか

「エンタメでなくていい、限りなくアートでいい、物語すら無くていい、
とにかく壮観で心を圧倒するものを」という依頼から出発した。
なので最初に、**何が人を圧倒するのか**を決めないと手が動かない。
以下がその分析で、この作品はここに賭けている。

### 1. 芸術は意味を運ぶ器ではない

要約で置き換えられる作品は、要約の容器だったということ。
芸術と呼ぶに値するのは、**それ自身の説明で置き換えられないもの**だけだ。
だからここには物語も主題も台詞もない。意味を抜いたあとに残るのは、
構造と光と時間そのものになる。残るものがある、という賭け。

### 2. 「圧倒される」とは、自分の尺度が効かなくなること

圧倒は大きさでは起きない。**通約できないこと**で起きる。
山の前に立って息を呑むのは、山が大きいからではない。
足元の砂粒と地平線の稜線が同じものでできていて、
その両方を一つの尺度で掴めないからだ。自分の物差しが壊れる。

だから、一枚の絵の中に、目が繋げられない二つの尺度を必ず同居させる。
この作品では **2 world unit の粒と 1800 unit の塊**が同じ画面にいる。
桁で言えば約3桁。しかもその間が連続していて、
全部が同じ一つの式から出ている。

### 3. 偶然は圧倒しない。必然だけが圧倒する

でたらめに置いたものは、人はすぐ「でたらめ」と見抜いて、見るのをやめる。
見続けさせるのは、**分かりかけているのに予測はできない法則**の感触だ。

だからここでは、形を一つも手で置いていない。モデルも図形もキーフレームもない。
雲も壁も海面も裂け目も、「密度場がある値を超えた場所」でしかない。
見る人はその式を言い当てられないが、**こうでしかありえない**とは感じる。
そこが狙い。

### 4. 圧倒は時間の関数である

エンタメは対象を取り替えて注意を保つ（カット、カット、カット）。
芸術は同じ対象を、**見る側の焦れが体験に含まれるまで**持たせないといけない。
1分を切ると、人はまだ「ショットを見ている」。そこを越えたあたりで、
ようやく「それ」を見はじめる。

だから一楽章は72秒以上。カットは一つもない。楽章の移り変わりは
式のパラメータが溶けていくだけ。
そして遅さは、絵を成立させる条件でもある。描き手は前のフレームに
少しずつ混ぜて画質を稼ぐので、**視点が遅いほど絵が綺麗になる**。
辛抱がそのまま解像度になる。

### 5. 全部見せたら、そこで終わる

見せ切ったものは消費されて捨てられる。この作品の暗さは気分ではなく、
**構造上の条件**だ。画面の大半は暗く、光源はたいてい画面の外にあり、
壁の上端も端も決して入らず、裂け目は上下の枠を突き抜けていく。
見る人は足りない部分を勝手に埋める。自分で埋めた世界は、
見せられた世界より必ず大きい。

### 6. 作者が見えると、圧倒は消える

崇高なものは、こちらに関心がない。題字・署名・UI・顔——どれも
「誰かがあなたのために作った」と告げてしまい、見る人を人間の寸法に連れ戻す。
だから画面には何も出さない。文字も、顔も、記号も、操作も、ロゴも。
シリーズ名が《無銘》なのはそういう理由で、操作キーはこの文書にしか書いていない。

### 7. 一点ものは続かない —— ここが「作り続けるための基軸」

作品が「物」なら、作り続けるとは物を増やすことで、いつか枯れる。
作品が**「法」と「種」**なら、やることは法を磨くことだけになり、世界は尽きない。
これが基軸のうち唯一、一作のためではなく**継続のため**の項だ。

一作 = 種（seed）＋ 譜（score）。同じ法の別の解。
一つ終われば次の種の作品が始まる。その作品は誰も見たことがない。
**作った本人も見ていない。**

## 基軸 —— 五法

上の分析を、手が動く形まで落としたもの。
毎回これで自分を検査する。**守れているかを機械が測れる形にしてある**のが要点で、
「美しいと思う」では次の一作の指針にならない。

| | 法 | 意味 | どう実装しているか | どう検査するか |
|---|---|---|---|---|
| 一 | **法** | 世界は一つの式から出る。形を直接置かない | 密度場 `field()` の閾値越えだけが物質になる。楽章はパラメータを差し替えるだけ。譜に形を書く欄が無い | 譜に未知の欄を書くと `merge()` が例外で落ちる。場の周期 > 視程（繰り返しが見えない）も検査 |
| 二 | **尺** | 一枚の絵に、目が繋げられない二つの尺度を同居させる | 場のテクスチャ1回で4オクターブ。近景でさらに2回引いて 2 unit まで下ろす。遠景は 1800 unit | 焼いた絵の多重解像度分解。1〜2画素の帯と128画素の帯の両方にエネルギーがあること |
| 三 | **間** | カットを持たない。一楽章72秒以上。転換は溶解だけ | 譜にカットを書く欄が無い。転換は全パラメータの smoothstep 補間 | 0.25秒あたりのパラメータ変化が全振幅の6%未満。焼いた絵の0.5秒差が5%未満（実測1.97%／カットなら8.3%） |
| 四 | **闇** | 画面の大半は暗い。全部は見せない | 光源は画面外。周辺は落とす。壁の上端・裂の両端は枠外 | 線形輝度の中央値が0.13以下、かつ上位1%が0.030以上（暗いだけの絵は闇ではない） |
| 五 | **種** | 作品は一点ではなく「種＋譜」。同じ法から無限に別の世界 | すべて `seed` から決まる。`Math.random()` を使わない。視点は固定歩幅で積む | 同じ種から同じ譜が出ること。同じ引数の書き出しがバイト単位で一致すること |

### 禁

五法が「やること」なら、こちらは「やらないこと」。

- **文字を画面に出さない**（題名・署名・字幕・説明・年号）
- **顔と人体を出さない**。目が顔を見つけた瞬間、絵は人間の寸法に戻る
- **記号を出さない**（矢印・図形・ロゴ・UI）
- **拍を作らない**。拍が入ると体が数えはじめ、時間が「長さ」として意識される
- **明確な結末を作らない**。解決した世界は閉じて、見た人を追い出す
- **ループの継ぎ目を見せない**。繰り返しが見えると、世界は有限になる

## 作品の構造

| ファイル | 役目 |
|---|---|
| `js/law.js` | **法**。密度場と光の式（GLSL）。この世界のすべてがここから出る |
| `js/compose.js` | **譜**。作品データ。数だけで、関数も DOM も持たない。五法の検査もここ |
| `js/render.js` | **描き手**。WebGL2 の三段（体積→蓄積→整色）。美の判断を持たない |
| `js/drone.js` | **音**。同じ譜から合成する持続音。音声ファイルは無い |
| `js/main.js` | **進行**。譜を時計で解いて描き手と音に渡す |
| `js/rng.js` | 種から決まる乱数 |
| `tools/` | 書き出しと検証（作品の一部ではない） |

守るべき関係は `rivals/` と同じ思想で、

- **ルールは法（`law.js`）にある。描き手（`render.js`）はルールを持たない。**
  描き手が持っているのは負荷対策（解像度と歩数の自動調整）だけで、
  それは絵の作りに影響しない。
- **譜（`compose.js`）は数だけ。** 形を置く欄が無いので、
  「この楽章だけ手で雲を足す」ができない。これが「一・法」の担保。
- **乱数は必ず `rng.js` を通す。** `Math.random()` を書いた瞬間に
  「五・種」が死ぬ。

### 五つの楽章（無銘 一番）

同じ密度場のパラメータ違い。別の世界に見えるが、一つの法の別の解でしかない。

| | 楽章 | 長さ | 何が起きているか |
|---|---|---|---|
| 1 | 塵 | 96秒 | 希薄な媒質。逆光の前方散乱だけがある。まだ何も形になっていない |
| 2 | 壁 | 108秒 | 垂直の塊。上も下も端も画面に入らない。全体は決して見えない |
| 3 | 潮 | 96秒 | 物質が面を作る。水平線が生まれ、低い光がそれを横切る |
| 4 | 裂 | 120秒 | 太陽が落ちる。蛇行する裂け目だけが光源になる。全体の頂点 |
| 5 | 燼 | 84秒 | 物質が解ける。最後に残るのは近くの粒だけ。解決はしない |

転換は14〜20秒かけた溶解で、カットは一つもない。
終わったあと7秒の無があり、次の種の作品が始まる。

## 動かしかた

`art/index.html` をブラウザで開く。WebGL2 が必要。
ES モジュールを使っているので、手元で見るときは http で配ること。

```bash
python3 -m http.server 8899      # リポジトリのルートで
# → http://127.0.0.1:8899/art/index.html
```

画面には何も出していないが、キーは効く（**操作は作品の一部ではない**）。

| キー | |
|---|---|
| `1`〜`5` | その楽章の頭へ |
| `←` `→` | 30秒戻る／進む |
| `space` | 止める／動かす |
| `F` | 全画面 |
| `M` | 音を切る |
| `N` | 次の種の作品へ |
| `H` | 楽章名・時刻・解像度・歩数・fps を出す |

重い機械では、内部解像度（34〜100%）と光の歩数（52〜120）が自動で下がる。
**構図は変わらない。**遠くが粗くなるだけ（歩幅は「歩数がいくつでも同じ距離に届く」ように毎フレーム解いている）。

### 検証

```bash
node art/tools/check-axis.mjs 400     # 譜を400種ぶん、五法で検査
node art/tools/measure.mjs 0          # 焼いた絵を闇・尺・間・種で実測
art/tools/capture.sh out.png 400      # 400秒の絵を1枚書き出す
```

`check-axis.mjs` は「そう書いたか」しか見られない。
闇の量・尺度の同居・カットの無さは絵でしか測れないので `measure.mjs` が
実際に焼いて測る。粒（grain）は切って測る（高周波の雑音が細部の測定を
底上げしてしまうため）。

#### 実測（種 0・512×288・蓄積12枚・140歩）

```
楽章      時刻   闇:中央値  上位1%  暗部率 |  尺:細部(1-2px) 構造(128px)  比
塵        53s    0.0301  0.2398    39% |       0.0052      0.0787  15.0
壁       155s    0.0248  0.2080    46% |       0.0037      0.0618  16.7
潮       257s    0.0259  0.4731    45% |       0.0042      0.0856  20.2
裂       366s    0.0111  0.8512    60% |       0.0062      0.1034  16.8
燼       466s    0.0205  0.1003    49% |       0.0043      0.0535  12.3

間  楽章の中     252s → +0.5秒 の平均変化 0.243%
間  転換の最中   212s → +0.5秒 の平均変化 1.967%
    （対照）別の楽章どうしを並べると 8.312%  ← カットはこの桁になる
種  同じ引数の書き出しはバイト単位で一致
```

**「間」の対照値が要**。閾値だけ置いても「その数字が小さいのか」が言えないので、
本当にカットした場合の値（8.3%）も一緒に出している。
いちばん急な溶解でもその4分の1以下、という形でしか「カットが無い」は言えない。

「尺」の比の列は、128画素規模の構造エネルギーが1〜2画素の細部エネルギーの
何倍あるかで、**両方に量があること**が基軸の中身。
片方がゼロなら（＝ぼやけた絵か、砂嵐）この列は意味を持たない。

`capture.sh` には検証用にパラメータを上書きする口がある。

```bash
art/tools/capture.sh out.png 170 800x450 12 150 0 "ridge:0.8,thresh:0.66"
```

これは**値を詰めるための道具で、作品の一部ではない**（`?t=` が付いた
静止画モードでしか効かない）。

## 増やしかた

**新しい作品を作るのに、コードを書く必要はない。**
`?seed=N` を変えるか `N` キーを押せば、同じ法の別の世界が出る。
500種ぶんは五法を満たすことを確認済み（`check-axis.mjs 500`）。

法そのものを育てるときは、この順で触る。

1. **楽章を足す** … `compose.js` の `ARCHETYPES` に1件足す。
   パラメータだけ。72秒以上、転換10秒以上。`check-axis.mjs` が見張る。
2. **法に項を足す** … `law.js` の密度場か光に項を足し、
   `compose.js` の `BASE` に既定値を入れ、`render.js` の uniform 名の列に加える。
   **既定値は「その項が無かったときと同じ絵になる値」**にすること。
   そうすれば既存の譜が壊れない。
3. **絵の性格を変える** … `ridge`（丸い塊↔削られた襞）、`warp`（渦）、
   `thresh`（どれだけの空間が物質になるか）、`density`（塊の不透明さ）が効く。
   `thresh` と `density` は連動していて、**「まばらで不透明」が塊に見え、
   「一様で半透明」は霧にしか見えない**。

触るときの注意が2つある。どちらも実際に踏んだ穴。

- **場の統計は GPU で実測している。** `ridge` を上げると密度場の平均と
  散らばりが動き、**種を変えても動く**（場の一番低い周波数の格子点は
  3³=27 個しかないので、種ごとに平均が数%ずれる）。
  放っておくと同じ `thresh` が「空間が物質で埋まる」ことにも
  「何も無い」ことにもなり、譜が種をまたいで通用しない。
  `render.js` の `measureRidge()` が6点で焼いて読み戻し、
  平均を 0.5、散らばりを `FIELD_SD`（0.120）に揃えている。
  だから `thresh` は全楽章・全種で同じ意味を持つ。
  **新しい場の変形を足すときも同じように実測して打ち消すこと。**
- **光の行程は塊より長く見ること。** 太陽への遮蔽を100 unit しか見ていないと、
  数百 unit の塊でも「全面が明るい綿」になって立体に見えない。
  いま6歩で1600 unit 先まで見ている。ここを短くすると絵が平らになる。

## 分かっていること・限界

- **映像ファイルは吐かない。** その場で計算する作品として作ってある。
  記録が必要なら `tools/sequence.sh` で連番を書き出して ffmpeg でまとめられるが、
  **この環境（ソフトウェア描画）では1枚あたり十数秒かかる**ので、
  8分半を通しで焼くのは現実的でない。GPU のある機械で回すこと。
- **検証はソフトウェア描画で行った。** この環境に GPU が無いため、
  絵の正しさは確認できているが、**実機での fps は測っていない。**
  重い場合は自動で解像度と歩数が落ちる作りにしてある。
- **WebGL2 が無い端末では何も出ない**（その旨だけ表示する）。
- **浮動小数のテクスチャが無い端末**では、蓄積を8bitで行う経路に落ちる
  （わずかに階調が荒くなるが絵は出る）。
- 音は自動再生できないので、**最初の一触りで始まる**。
  その一触りが作品の開始を兼ねている。
