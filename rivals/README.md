# ライバルズ再現版（`/rivals/`）

かつて配信されていたカードゲーム「ドラゴンクエストライバルズ」（2017–2020）のルールを
再現した、ブラウザだけで動く一人用カードバトル。通信対戦はなく、相手はすべてコンピューター。

公開URL: `https://takeom5700.github.io/rivals/`

外部ライブラリなし。画像・音声ファイルなし（効果音は WebAudio で合成、絵はCSSと文字）。
素の静的ファイルなので、GitHub Pages にそのまま乗る。

---

## 再現したルール

盤面は **3段（上・中・下）× 2列（前列・後列）＝ 6マス**。ここがこのゲームの肝で、
どこに置くかで攻撃できる／できないが変わる。

| 決まりごと | 内容 |
|---|---|
| ブロック | 同じ段の前列にユニットがいるとき、その後ろの後列ユニットは攻撃できない |
| ウォール | 3段すべてに敵ユニットがいるとき、敵リーダーを攻撃できない |
| におうだち | 前列にいるあいだ、敵はそれしか攻撃できない（後列では効果なし） |
| 貫通 | 攻撃対象の後ろのユニットにもダメージ。そのユニットからの反撃は受けない |
| ステルス | 自身が攻撃するまで、敵の攻撃・効果の対象にならない |

そのほか

- リーダーHP 25／デッキ30枚／同名3枚まで（レジェンドは1枚）
- MP上限は毎ターン+1、最大10。消費したMPはターン開始時に全回復
- 先攻は手札3枚、後攻は手札4枚＋テンションゲージ2段階＋「まほうのせいすい」（MP+1）
- 手札上限10枚、山札が尽きたあとは引くたびに増えるダメージ（デッキ切れ）
- テンションを3段階ためるとリーダー固有のテンションスキル（MP消費なし、使うと0に戻る）
- 武器を装備するとリーダー自身が攻撃できる（耐久力を消費、反撃も受ける）

### 7人のリーダーとテンションスキル

| 職業 | リーダー | テンションスキル |
|---|---|---|
| 戦士 | テリー | 稲妻の加護 — このターン中、味方リーダーは攻撃力+3と貫通を得る |
| 魔法使い | ゼシカ | 紅蓮の火球 — 敵ユニット1体に3ダメージ |
| 僧侶 | ククール | いやしの波動 — 味方キャラすべてを3回復 |
| 武闘家 | アリーナ | おてんば姫 — カード1枚と武術カード1枚を引く |
| 商人 | トルネコ | お宝発見 — ランダムな道具カードを3枚手札に加える |
| 魔剣士 | ピサロ | 魔族の騎士 — 3/2のピサロナイトを召喚 |
| 占い師 | ミネア | 水晶占い — デッキから特技カードを1枚引き、コストを-1 |

占い師のタロットは①②のどちらかがランダムで発動する。「銀のタロット」などで
**必中モード**にすると、自分で選べる。

### 原作との違い（正直なところ）

- **カードの数値と効果は再構成**。公開情報と記憶をもとに組み直したもので、
  原作のカードプールとは一致しない。収録は180枚（原作は1000枚超）。
- カード名は原作・ドラクエシリーズのものを使っているが、性能は別物と思ってよい。
- 原作のイラスト・音声・ボイスは一切使っていない。
- 「テンションリンク」「選択」など、原作にあって未実装の特性がある。
- 調査時、公式サイトと攻略Wikiへの直接アクセスができなかったため、
  テンションスキルなど一部は検索結果の記述に基づく。

## ファイル構成

```
rivals/
  index.html          画面の骨組み（タイトル／リーダー選択／バトル／デッキ編集／図鑑／ルール）
  css/style.css       見た目。配色はサイト本体（タケオの縁日）に合わせた
  js/
    cards.js          カード184枚の定義（うちデッキに入るのは180枚）（効果は関数で書く）＋テンションスキル
    engine.js         ルールの本体。ブロック・ウォール・におうだち・貫通・死亡処理
    ai.js             コンピューター。ビームサーチ＋評価関数
    decks.js          プリセットデッキ14種と、デッキの正当性チェック
    ui.js             バトル画面。操作の可否は engine.legalActions() だけを見る
    builder.js        デッキ編集とカード図鑑
    view.js           カード表示の共通部品
    storage.js        localStorage（自作デッキ・戦績・設定）
    audio.js          効果音（WebAudioで合成）
    rng.js            決定論的乱数。AIが盤面を複製して先読みするため state に載せる
```

### 設計で気をつけたこと

- **状態は素のデータだけ**。関数や DOM 参照を持たないので、`JSON` で丸ごと複製でき、
  AI が「この手を打ったらどうなるか」を本物のエンジンで試せる。
- **画面はルールを持たない**。押せる／押せないは全部 `legalActions()` から引くので、
  画面とルールがずれない。
- 乱数は `state.rng` に載せる。AIの先読みでも再現性がある。

## コンピューター対戦相手

難易度は「読みの深さ」だけでなく **何を理解しているか** で分けている。
ライバルズは前列後列の使い分けが勝敗を分けるゲームなので、そこを分からせるかどうかを
difficulty の軸にした。

| 難易度 | 探索 | 理解していること | わざと間違える確率 |
|---|---|---|---|
| かんたん | 幅1・手順3 | 良い交換だけ。MPも余らせる | 30% |
| ふつう | 幅3・手順7 | 良い交換。前列後列は分からない | 8% |
| むずかしい | 幅8・手順16 | ブロック・ウォール・におうだち。返しの打点も数える | 0% |
| げきむず | 幅12・手順24 | 上に加えて、ターンを終えたあと相手が何をするかまで読む | 0% |

タイプは評価の重み。アグロ／ミッドレンジ／コントロール／コンボ／テンポの5種類で、
同じデッキでも動き方が変わる。

### 強さの実測（ミッドレンジ同型・席と先攻後攻を均等にして各200戦）

| 対戦 | 勝率 |
|---|---|
| ふつう vs かんたん | 93% |
| むずかしい vs ふつう | 79% |
| げきむず vs むずかしい | 55% |
| むずかしい vs かんたん | 99% |

1手あたりの思考時間は かんたん1ms / ふつう2ms / むずかしい3ms / げきむず12ms 程度。

> 補足：最初の実装では「毎手ごとに読み直す」作りだったため、探索を深くしても
> 強さが変わらなかった（浅い読みでも打ち直せてしまうため）。
> 手順はターンの頭に一度だけ組み立てる作りに変えて、初めて階段になった。

## 動かしかた・テスト

静的ファイルなので、適当なサーバで開けば動く（ES modules を使うため `file://` は不可）。

```bash
python3 -m http.server 8799
# http://127.0.0.1:8799/rivals/
```

リポジトリには npm の設定を置いていない。検証は使い捨てのスクリプトで行った。

- ランダム自己対戦400戦でエンジンの例外を確認（0件）
- AI同士の総当たりで難易度の階段とデッキ勝率を計測
- Playwright（Chromium）で、タイトル→リーダー選択→対戦→決着までを実際に操作

## 既知の傾向

- **先攻・後攻の釣り合いはおおむね取れている**。14デッキのミラー戦（各64戦）で
  先攻の平均勝率は56%。ただしデッキごとの振れ幅は大きく41〜72%（速い形ほど先攻が有利）。
  後攻の補正は原作どおり手札+1枚・テンション2段階・まほうのせいすい。
- デッキ間の勝率差は3割〜7割程度。速い形が強めで、受ける形がやや不利。
- 一人用なので、相手の難易度とタイプを選んで釣り合いを取る前提にしている。

## やっていないこと

- 通信対戦・ランクマッチ
- カードの入手（パック開封）や資産管理。全カード最初から使える
- 原作の特性のうち「テンションリンク」「選択」など
